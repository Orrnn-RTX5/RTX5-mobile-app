React Native on-chart position controls
Verification date: 2026-10-14

Implemented within the existing position store, chart overlay model, live quote
bridge, WebView renderer, modification coordinator, and authenticated trade APIs.

The entry line remains at the actual executed price. Each ticket has readable
side, remaining lots, floating P/L and account currency, details/actions access,
and close access. TP and SL remain visible in portrait and landscape, with teal
and amber chips matching the supplied web-terminal reference. Wide layouts also
expose Share, Add and Reverse; narrow layouts keep those secondary actions in
the native Position actions sheet. Nearby labels
stack with connectors to their actual entry prices; overflow opens a ticket
selector. Existing live price/countdown presentation remains independent.

Complete confirmed position receipts merge into the existing store immediately.
The existing fill retention and ledger reconciliation handle subsequent reads.
Structural socket updates fence older in-flight REST reads; confirmed terminal
updates use the existing close tombstones to prevent a late fill resurrecting a
closed ticket. Partial and full closes update active controls and levels.

Broker profit is preferred. Fresh liquidation quotes (BUY Bid / SELL Ask) can
produce explicitly marked, broker-snapshot-calibrated estimates. Missing broker
profit/currency remains unavailable rather than becoming fabricated USD profit.
Entry/TP/SL prices and main price-scale formatting use instrument digits/ticks;
remaining volume formatting preserves broker volume-step precision.

All authenticated requests remain native. Scoped, typed intents validate ticket,
symbol, account-session namespace, chart context/generation, request ID and level
role/price. Duplicate intents and overlapping position mutations are blocked.
Pending modification/trade states replay for the current presentation. Chart
context and visual-shell changes invalidate old intents, including switching
away from a symbol and back again.

Close retains the position until broker confirmation. Add submits a new order at
the latest remaining volume. Reverse explicitly confirms closure before sending
the opposite order and separates replacement failures from close failures.
Sharing has an explicit native preview containing display data only.

TP/SL uses the existing exact-ticket native modification host and coordinator.
The client snaps prices and checks supplied tick, stop/freeze and liquidation
side rules. Profitable trailing stops are allowed on the correct market side.
Executed entry prices are not draggable. Position stops require a deliberate
hold; release submits once, cancellation/rejection restores broker levels in
both chart previews and the selected native panel. Pinch/pan gestures over a
control cannot execute its action.

Concrete API limitations:
- A canonical fill receipt can omit side/symbol/remaining volume. Incomplete
  receipts and netting increases/decreases/reversals wait for the existing scoped
  ledger reconciliation; the frontend never guesses a weighted entry/volume.
- Existing-position SL/TP is disabled, with the broker capability explanation,
  whenever the active broker has not enabled that existing backend capability.
- The existing modification API/coordinator requires positive safe-integer
  tickets/accounts. Larger string tickets remain exact in overlays and full
  close requests, but their modification controls explain the API limitation.
- Stop/freeze metadata is enforced when supplied. Absent/dynamic distance rules
  remain authoritative at the broker; rejected requests retain actual levels.
- Add/reverse is disabled if the broker's volume bounds/step are unavailable or
  the remaining volume cannot satisfy them. Margin validation uses the existing
  order API. Reverse is a sequential close/open flow, not an atomic transaction.
